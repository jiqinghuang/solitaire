# 纸牌接龙 · Solitaire

> **在线试玩：<https://jiqinghuang.github.io/solitaire/>** — 打开即玩，无需安装

经典 Windows **Klondike 纸牌接龙**的网页复刻：绿呢牌桌、Win95 灰面板、双层 bevel、七段 LED，全部纯 CSS + 内联 SVG，**零图片、零字体、零运行时依赖**。

## 玩法

打开 `index.html` 即玩：

- **牌阵**：7 列。红黑交替、点数递减叠放；**空列只能放 K**。
- **收牌区**：右上角四个，按花色从 A 到 K 依次累积。收满 52 张即胜利。
- **牌库**：点一下翻牌进废牌堆；牌库空了再点一次，把废牌堆整体回收重翻。
- **拖动**：按住明牌拖动，可连同下面整段合法牌组一起移动。
- **点选**：先点一张牌选中，再点目标列放下（触屏更顺手）。
- **双击**：顶牌直接送进对应花色的收牌区。
- **撤销**：`Ctrl+Z` 或菜单，可撤销最近 200 步操作（包括翻牌和自动翻开的牌）。
- **提示**：`H`，高亮一条推荐走法并给出文字说明。
- **分析局面**：底栏按钮或按 `A`，调用求解器判断可胜 / 死局 / 暂不确定。
- **自动完成**：牌库清空、所有牌翻开后可用，逐张把牌收进收牌区。
- **抽牌模式**：菜单可切「翻一张 / 翻三张」；切换会重新发牌。
- **键盘**：`F2` 新游戏、`Ctrl+Z` 撤销、`H` 提示、`F` 自动完成、`A` 分析局面、`Esc` 关菜单；`Alt+G` / `Alt+H` 展开菜单。
- **标题栏**：保留两个 Win95 按钮——最大化铺满屏幕（再点还原）、最小化只留标题栏（点标题栏展开）。
  网页版不画只能假关闭的「×」；关闭标签页是浏览器自己的职责。
- **触屏**：点按选中、点目标放下；也可以直接拖动。

胜利后会播放经典纸牌的四花色弹跳动画。

## 死局会怎样？

Klondike 本身不是每局都赢——模拟统计下，**翻一张约八成可胜，翻三张只剩不到两成**。
所以死局大多不是你的错，而是那局牌本来就无解。

本项目把「死局」从一个模糊的挫败感变成**可判定、可解释**的状态：

- **自动检测**：每次走子后快速检查；真没得走了就弹出面板，直接告诉你「这局已经无法继续」，
  并列出**为什么**：哪张牌被埋住、某张牌在等哪张牌、收牌卡在第几步、腾不出空列等等
- **底栏「分析局面」按钮 / 菜单「分析局面」**（或按 `A`）：跑真正的求解器，给出三态结论：
  - **还能赢** —— 这局有解，并直接告诉你**必胜第一步**该怎么走
  - **已死局** —— 无论怎么走都赢不了，建议撤销或重新发牌
  - **暂不确定** —— 牌局太复杂，限定时间内没搜出结论（不骗你说输赢）
- **自救手段**：`Ctrl+Z` 撤销（最有效）、把收牌区的牌移回牌阵、重新发牌

求解器用带转移表的 DFS，设了节点与时间上限；超限返回「不确定」而不是乱猜。
它的走法生成与引擎**逐一对拍**（见测试），保证两套规则判定完全一致。

两个容易搞错的规则细节，实现里都按真实规则处理：

- **回收废牌堆不是万能解**：翻三张时回收只是把同样的分组再翻一遍（原地打转），
  但翻一张时回收会把整叠掉头，翻出原本埋在堆底、从未露面的牌——所以死局判定必须分模式处理，
  否则会把还能玩的局误报成「已无法继续」。
- **收牌区的牌可以拉回牌阵**：这是真实纸牌允许的自救手段，求解器必须同样允许，
  否则会把可胜局判成死局。

## 工程结构

```
index.html        页面骨架 + 规则说明
style.css         经典 Win95 + 绿呢牌桌外观（纯 CSS，响应式牌宽）
src/engine.ts     游戏核心：发牌、叠放规则、翻牌/回收、撤销、提示、自动完成，零 DOM 依赖
src/solver.ts     求解器：死局判定（可胜 / 死局 / 搜不出来）、必胜路线与原因诊断，零 DOM 依赖
src/ui.ts         渲染与交互：指针拖动、点选、双击、菜单、LED、计时、胜利动画、死局面板
src/palette.ts    花色配色的色彩科学校验（OKLCh 色相 + WCAG 对比度，读 style.css 实值）
src/layout.ts     响应式布局校验（牌宽 clamp 公式在几十种视口下不溢出）
src/test.ts       引擎 + 求解器测试（含与引擎的走法生成对拍）
src/uitest.ts     UI 接线测试（最小 DOM stub 真正执行 dist/ui.js）
dist/             tsc 编译产物，随仓库提交（线上加载的就是它）
```

> `dist/` 提交进仓库是为了「克隆下来双击 index.html 就能玩」。代价是必须记得 `npm run build`，
> 所以 CI 会重新编译并校验 `dist/` 与 `src/` 逐字节一致，不一致直接报错并给出修复命令。

## 常用命令

```bash
npm install           # 装 devDependency（只有 typescript；运行时零依赖）
npm run build         # 编译 src/ → dist/
npm run typecheck     # 仅类型检查
npm test              # build + 引擎 + UI + 配色 + 布局校验
```

## 设计要点

- **引擎与 UI 彻底分离**：engine / solver 不知道 DOM 存在，全部规则可被 node 直接测试
- **撤销是反向操作记录**：每条只存「从哪到哪、翻开了哪张、元状态」，约几十字节；
  自动翻牌、回收、胜负状态一起回滚，不会出现「撤回去牌面不一致」
- **回收是物理翻堆**：废牌堆整叠掉头扣回牌库，重翻顺序与真实洗牌一致
- **随机源与时钟可注入**：测试用种子 PRNG 复现任意牌局；计时从首操作开始、胜利冻结
- **指针事件统一鼠标与触屏**：拖动超过阈值才视为拖拽，避免点按误判
- **牌宽随窗口自适应**：`clamp(30px, calc((100vw - 预留) / 7), 132px)`，
  窗口大时牌也大（1920px 屏幕上牌桌占 54% 宽，旧版固定 96px 只占 40%），
  小屏自动缩到 30px 下限。预留量算错就会出横向滚动条，
  所以 `src/layout.ts` 在 27 种视口宽度上验证「不溢出 / 单调 / 上下限」
- **花色配色按 OKLCh 构造，不凭感觉调 RGB**：红黑交替是游戏规则，所以颜色本身就是信息。
  两个「红」的色相必须都在 35° 以下（纯红是 29°，超过就偏橙、可能被误读成第三色），
  四个花色对牌面的对比度必须全部达到 WCAG AA（4.5），两个「黑」必须同色相仅差明度。
  这三条约束写成了 `src/palette.ts` 的断言，改颜色改错了 CI 会直接失败
- **渲染按牌堆签名增量更新**：牌面没变的列不重建 DOM；撤销/换局/窗口缩放时强制全量重绘
- **分析局面不阻塞界面**：先让「正在分析」上屏，再跑搜索；期间若撤销或开新局，旧结果自动作废
- **`dist` 与 `src` 同步校验**：CI 重新编译后 diff 必须为空，防止改了源码忘 build
